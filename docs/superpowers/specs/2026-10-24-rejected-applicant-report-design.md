# Rejected Applicant Access and Formal Report Header

## Intent

An applicant who fails a recruitment stage must immediately lose portal access. The existing account is retained so that its application history remains intact. Formal report PDFs must follow the centered, official-style header shown in the supplied reference, identify the generating role, retain the generation timestamp, and number every page.

## Goals

- A failed recruitment-stage result sets the corresponding applicant profile to inactive, invoking the existing Supabase Auth ban/session revocation trigger.
- The account stays disabled until HR explicitly reactivates it for a new application after the six-month cooling-off period. This change does not delete applicant history or invent a separate public registration workflow.
- PDFs center the agency/station header and report title; they show `Generated by`, `Generated on`, and `Page N of M`.

## Non-goals

- Changing applicant registration, credentials, or the existing HR reactivation/resubmission workflow.
- Reproducing the supplied memorandum artwork or seals.
- Changing CSV exports or on-screen report tables.

## Approaches

1. Disable the profile in the existing HR stage-result transaction (chosen). It reaches the existing Auth enforcement trigger and is atomic with the decision/history/notification.
2. Add a separate trigger on every application update. This is broader and could disable accounts during historic corrections or an HR-led resubmission.
3. Enforce only in the Next.js login route. This would leave active sessions and database authorization intact.

For report metadata, the chosen approach passes the authenticated user's display name into the existing protected PDF builder. Deriving it inside the client would be untrusted and would miss direct PDF downloads.

## Constraints and verification

- Database code retains `SECURITY DEFINER` search-path and permission patterns already used by recruitment RPCs.
- New database assertions first demonstrate that a failed stage currently leaves the profile active, then verify the profile/Auth access is blocked after the migration.
- PDF tests first demonstrate the absence of centered metadata/author output, then verify the formal header and page numbering.
