# HRIS Feedback and Applicant Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Deliver the approved HRIS feedback while preserving private data, workflow history, and existing employee records.

**Architecture:** Implement shared applicant identity/profile and private media first. Build recruitment workflow changes on that foundation, then update the independent personnel and deployment modules. Database RPCs are the source of truth for transitions and file ownership; React invokes typed client helpers.

**Tech Stack:** Next.js/React, TypeScript, Zod, TanStack Query, Vitest, Supabase Postgres, Storage, RLS, PL/pgSQL.

**Spec:** docs/superpowers/specs/2026-09-07-hris-feedback-and-applicant-profiles-design.md

## Global Constraints

- Applicant Number is immutable, unique, server-generated, and displayed as 0-12345.
- Badge Number remains employees.employee_number, is entered by HR at hiring, and is the only user-facing employee identifier.
- Profile media and documents are private; never expose a service-role key or a public URL.
- Notes are optional everywhere in this scope.
- Existing job/application/deployment history and historic deployment end dates are preserved.
- Run focused tests before every commit and the complete verification set before delivery.
