# Final PDF recruitment and attendance implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve applicant identity/recovery across recruitment windows and make attendance hours, time format, and late calculation accurately reflect the 05:00 access window and 08:00 duty start.

**Architecture:** Keep the existing applicant-number allocator as the durable identity, adding reactivation/cycle state rather than replacing applicant or application rows. Keep attendance source events immutable and derive duration/late display from timezone-aware server rules that distinguish scanning access from scheduled work start.

**Tech Stack:** Next.js 16 / React 19, TypeScript, Supabase Postgres/RLS, Zod, Vitest, pgTAP, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-final-pdf-per-tab-revisions-design.md`

## Global Constraints

- Generate imperative migrations with the Supabase CLI and retain all applicant/attendance history.
- Applicant number is assigned independently of documents and qualification and is never reused.
- HR-only reactivation/credential issuance cannot disclose another applicant's record.
- 05:00 is the earliest valid attendance scan; 08:00 remains the scheduled start used for late classification.
- Use `Asia/Manila` consistently for database/business-time calculations and display 24-hour times.

## Review Focus

- Concurrent registrations receive different applicant numbers even if neither has documents; cover this in Task 1.
- A disqualified applicant can be reactivated without losing applications/documents, while an unauthorized caller cannot reactivate them; cover this in Task 1.
- A third recruitment window is rejected only when it represents a new yearly window, not an ordinary job opening inside an allowed window; cover this in Task 1.
- A 05:00-07:59 scan is accepted and not late, while an 08:00-plus scan follows configured grace; cover this in Task 2.
- Missing time-out has no invented duration and remains visibly incomplete; cover this in Task 2.
