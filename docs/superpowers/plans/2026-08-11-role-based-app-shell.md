# Role-Based App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished, responsive, server-protected application shell and landing page for every HRIS role.

**Architecture:** A protected route group renders an authenticated shell with a root TanStack Query provider. Small nested server layouts call one role guard before serving each role root, while typed role/navigation configuration drives the shell UI. shadcn/ui primitives provide the responsive sidebar and accessible building blocks.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, shadcn/ui, Lucide React, TanStack Query v5, Vitest, Testing Library.

## Global Constraints

- Work only on `feat/03-role-based-app-shell`; do not add database migrations, Supabase policy changes, Storage changes, or Edge Functions.
- Keep the five existing roles and enforce a matching role on the server; UI hiding is never the authorization boundary.
- Keep `/applicant/register` public; unauthenticated protected requests still go to `/login` through `src/proxy.ts`.
- Authenticated mismatches, missing roles, and invalid roles redirect to `/unauthorized`.
- Use the existing Tailwind v4 semantic CSS tokens and shadcn/ui components generated by the current CLI; use Lucide icons only.
- Support keyboard navigation, a skip link, visible focus rings, accessible names, 4.5:1 normal-text contrast, no color-only state signals, and responsive behavior beginning at 375px.
- Management must have no mutation controls. Future feature branches own module links, query functions, mutations, and cache invalidation.

- [ ] **Step 3: Write the smallest explicit guard and configuration**

```ts
export async function requireRole(expectedRole: AppRole) {
  const user = await getAuthenticatedUser();
  if (!user) redirect("/login");
  const role = await getCurrentRole();
  if (role !== expectedRole) redirect("/unauthorized");
  return { user, role };
}

export type RoleConfig = {
  role: AppRole;
  label: string;
  homeHref: `/${string}`;
  landingTitle: string;
  landingDescription: string;
  navigation: readonly { href: `/${string}`; label: string; icon: "LayoutDashboard" }[];
};
```

Create exactly five `ROLE_CONFIG` entries: System Administrator → `/admin`, HR Personnel → `/hr`, Employee → `/employee`, Applicant → `/applicant`, and Management → `/management`. Each navigation array contains only its own landing route.
