# Final PDF deployment and personnel implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the PDF-required deployment, personnel-record, profile-correction, and leave workflows without deleting historical records.

**Architecture:** Replace the single-employee deployment record with a header-and-assignment model, keeping existing deployments readable through a compatibility view/query. Extend the established employee-owned request and HR-decision RPC pattern for all HR-entered profile data, and represent excess leave as a reviewable value rather than a payroll action.

**Tech Stack:** Next.js 16 / React 19, TypeScript, TanStack Query, Supabase Postgres/RLS/Storage, Zod, Vitest, pgTAP, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-final-pdf-per-tab-revisions-design.md`

## Global Constraints

- Generate imperative migrations with `supabase migration new`; do not alter historical migrations.
- Keep user-owned storage uploads private and enforce employee ownership in SQL, not only in the client.
- Use RLS on every public table, explicit `TO authenticated` policies with ownership predicates, FK indexes, and `SELECT`-wrapped auth calls in policies.
- HR reviews employee evidence and may cancel assignments; only the assigned employee creates proof/status submissions.
- Use English user-facing copy, preserve history, and do not represent an external payroll deduction as completed.

## Review Focus

- A selected employee who becomes on leave or overlaps an assignment before submit is rejected by the RPC; cover this in Task 1.
- An employee cannot upload evidence or propose a status for another employee's assignment; cover this in Task 2.
- An employee cannot bypass supporting-document requirements for profile corrections; cover this in Task 3.
- A zero-credit leave request cannot submit until the employee explicitly confirms the computed excess; cover this in Task 3.
- Retired personnel remain readable in history but cannot be selected for a new deployment; cover this in Task 2.
