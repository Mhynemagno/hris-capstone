# Final PDF promotion and reports implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace manual promotion configuration with auditable rank-band readiness evaluation and generate formal, downloadable PDF reports.

**Architecture:** Persist the three supplied rank-band scoring policies and compute an evidence-backed readiness result without mutating rank. Reuse the role-gated reporting RPCs as the source of truth, rendering a portrait PDF only after access/filter validation on the server.

**Tech Stack:** Next.js 16 / React 19, TypeScript, Supabase Postgres/RLS, Zod, PDF rendering library selected and pinned during implementation, Vitest, pgTAP, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-final-pdf-per-tab-revisions-design.md`

## Global Constraints

- Generate migrations via the Supabase CLI; do not rewrite existing criteria/evaluation history.
- The official rank bands are PLT-PLTCOL, PSMS-PEMS, and PCPL-PMSG; source values from PDF pages 18-20.
- HR may review evidence and decide For Approval/Approved/Rejected; no path automatically updates `employees.rank_id`.
- PDF reports are portrait, formal, English, and authorized through the same source data/RPC boundaries as their tabs.
- New security-definer helpers stay private, set an empty search path, check the caller, revoke default execution, and have indexed join/filter columns.

## Review Focus

- A candidate missing one required course appears with the specific gap rather than as qualified; cover this in Task 1.
- An inactive/retired employee cannot enter the readiness queue; cover this in Task 1.
- A non-HR caller cannot change policy/evaluation outcomes or read another role's PDF report; cover this in Tasks 1 and 3.
- Large report results remain portrait/readable and do not leak a full unfiltered dataset to the browser; cover this in Task 3.
- Existing evaluations remain readable after policy migration; cover this in Task 2.
